# 本文評価のClef Flash比較（2026-11-12）

**判断: この構成は採用しない。本番のモデル設定は変更していない。**

[評価案](clef-evaluation-plan.md)のA（現行）とB（本文評価のみFlash）を比較した。
開発用12問を各構成3回、合計72要求。速度目標の「質問別中央値の比率0.75以下、短縮2秒以上」を満たさないため、最終確認用8問とChoice Flashの試験には進んでいない。

## 結果

| 指標 | A: 現行 | B: 本文Flash |
|---|---:|---:|
| 回答可能10問の安定成功@10（3回中2回以上） | 9/10 | 8/10 |
| 必要情報をすべて回収@10（失敗要求も分母に含む） | 24/30 | 21/30 |
| 必要情報をすべて回収@all（同上） | 24/30 | 21/30 |
| 必須事実回収率（質問ごとの割合の平均） | 80.0% | 70.0% |
| 無関係な結果@10（成功・非空要求、質問平均） | 34.2% | 34.2% |
| 重複の占有（成功・非空要求、質問平均） | 1.40枠 | 1.40枠 |
| HTTP往復込み（質問別中央値の中央値） | 17.365秒 | 17.534秒 |
| サーバー時間（同上） | 10.792秒 | 11.019秒 |
| エラー / 全要求 | 4/36 | 7/36 |

速度判定に使う**質問別のB/A比率の中央値は0.994、短縮秒数の中央値は0.118秒**（負なら遅延）。サーバー時間の比率中央値は1.020。
失敗要求の短い応答時間を高速化として数えていない。各質問の成功要求の中央値で速度を計算し、エラー率を別に示した。失敗のある質問ではサンプル数が減り、Q16のBは成功1回だけである。クライアント時間にはこの実行環境のネットワーク経路が含まれ、ユーザー端末の体感値そのものではない。

必須ケースでAが返した事実をBが返せなかったペアは2件。これは本文の判定で特定資料を落とした観測ではなく、容量不足で検索全体が失敗したケースである。非必須の安定成功質問の損失は1問（Q16のBが容量不足で2回失敗し、成功が1/3回になった）。

根拠不足のQ17・Q18は充足率の分母から除外した。成功時の結果は0件で、関連資料が出ないことと正しい回答を生成できることは同一視していない。今回は `/search` だけを実行し、回答生成・回答検証の精度は測っていない。

## なぜ速くならなかったか

Bで成功した要求の本文評価は174呼び出し中、実際にFlashが11回、通常Clefへのフォールバックが163回（93.7%）だった。

同じバッチとプロンプトを維持し、完全な要求のUTF-8バイト数をトークン数の保守的な上界として使っている。Flash用の安全枠20,480を超える要求は、本文を切り捨てず通常Clefへ送る。この判定に通らないことは、実際のトークン数が必ずモデル上限を超えるという意味ではない。今回の結果は、この安全側のフォールバックを含む実用構成の比較である。

大半が通常Clefのままなので、Flash単体の速度や精度を十分測れたとはいえない。候補選別・Choice・通信も変えていない。次に検討するなら、本文を保持したままFlashに収まるバッチへ分割する別試験が必要になる。分割そのものの精度・呼び出し数への影響を、モデル変更と分けて比較する。

## 回収できなかった情報

Q11「都営バスGTFSの中国語・韓国語翻訳は2026年9月にも含まれるか」は、両構成とも必要な追記を取得できなかった。名古屋市SRTの翻訳テストデータと鉄道GTFSの較正資料を返しており、都営バスの根拠にはならない。

正解の `gtfs-bus-integration-research.md` は検索対象に存在する。Q16で返った同資料の `blob_sha` は原文確認時と同じ `c01f19af15d9677821d94736654b87b2d302703c` で、資料の同期欠落とは扱わない。Q11の本文評価はBでもすべて通常Clefへ戻っていた。共通の検索失敗として記録し、この実験では修正していない。現在のtraceは途中段階の全候補・全棄却理由を返さないため、厳密な脱落箇所は未特定。

その他の成功要求では、今回の実測範囲でA/Bの結果内容と順序が一致した。ただし採点は資料IDの一致ではなく、本文・タイトル・メタデータが必須事実を裏付けるかで行った。代替根拠も同じラベルで両構成へ適用している。

## 実行条件と限界

- プロンプト、しきい値、候補予算、バッチ、並列数、Choiceは固定。候補選別は現行の混合構成で、Choiceは通常Clef。1ページ10件の表示・ページ送りの契約も変更していない。
- 各構成1回の共通ウォームアップを集計外で実施。その後は直列。質問順でAB/BAを交互にし、同じ質問の実行順は繰り返しでも固定。質問ごとの先行条件まで完全に交差させた設計ではない。
- 実行環境のセッション終了後は、完了済みペアを保持して再開した。再開時も質問ファイルのハッシュ・コード・URLを照合し、追加ウォームアップや既存失敗の置換はしていない。
- 原文に基づくAIの暫定採点。利用者による独立確認や、独立した採点者による厳密な盲検評価は未実施。StationAPI文書が多く、過去の診断で使った測位・直通の質問も含む。一般的な精度の保証ではない。
- 最終確認用8問は未実施。根拠不足ケースは指定文書に範囲を限定しており、全コーパスに答えが存在しないことを証明する試験ではない。
