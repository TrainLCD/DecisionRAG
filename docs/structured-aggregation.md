# 根拠付き構造化集計

関連: #51。2026-11-16 JST。

## 対象と現在の状態

ユーザーが選択した最初の指標は「日本国内の公開GTFS提供バス事業者のうち、本番StationAPIで配信中の事業者の割合」。フィード・自治体・路線ではなく事業者を数える。曖昧な質問ではこの分母を自動補完しない。

`data/metrics/public-gtfs-operators.json` はレビュー対象の指標レジストリ兼読み取り専用スナップショット。現在は定義だけを登録し、population/supported は null。**全国母集団も本番集合も未確定であり、本番の対応率はまだ算出できない。** 実データを揃えず、架空fixtureの合格を全国の集計成功としない。

確認した既存資料:

- [StationAPI #1775](https://github.com/TrainLCD/StationAPI/issues/1775): 840件は2026-11-08の「未対応フィード」の初回調査。既存対応分を含む母数ではない。大阪府の追加漏れ、ステージングと本番の区別も記載されている。
- [全国の公共交通GTFSオープンデータ一覧](https://bustime.jp/GtfsAgency/gtfs_list/): 2026-11-16確認時の表示は1,076データ。鉄道・船を含む配布データ一覧であり、事業者の完全な一意一覧ではない。網羅を目指す旨の記載だけで全国の完全性を認定しない。
- [StationAPI README](https://github.com/TrainLCD/StationAPI): GTFSの追加には再ビルド・再配備が必要。devへのマージ、ファイルの保有、本番配信を同一視しない。

このため、必要な入力は「公開バスGTFSの全対象を確認した基準日時付き台帳」「フィード横断の事業者ID対応表」「同じ基準日時の本番配備コミットと有効な事業者一覧」。これらが不足する限り null と不足理由を返す。

## APIと画面

`/search` は従来どおり資料検索だけ。Jev経路の `/answer` は数値集計要求を非生成判定し、登録指標の単位・範囲・対応定義と照合する。通常の機能説明や一覧要求は従来の回答生成を維持する。旧Rustルール経路は明示的な切り戻し用で、この新機能を持たない。

追加フィールド `aggregation` は検索の `evidence / hit_count / pagination` と分離する。状態は computed / needs_clarification / unsupported_metric / missing_population / missing_supported_set / incompatible_scope / empty_population。数値未確定時は numerator / denominator / value を null にし、missing_requirements を返す。

集計に該当する回答はRustが確定した文章を返す。LLMの数値を途中表示せず、SSEは sources → result。通常回答の sources → draft → result は維持する。画面でも不足理由と資料一覧を表示する。算出時の出典はsource_refsから安全なリンクとして表示する。

集計結果は認証付きカーソルに保存し、ページ送りでは再推論・再集計しない。資料改訂、レジストリ更新、公開リポジトリ集合の変更で409を返す。Jevカーソルを `/search` と `/answer` の間で流用した場合も409。既存のRustルールカーソルのscope形式は変更しない。Web内の10件単位のページ送りはAPIに再要求しない。

判定は検索と同じJudgeインスタンスを使い、呼出数・バイト数・期限を共有する。通常回答は追加1判定、明確な集計は2判定、曖昧な集計は3判定。障害は既存の502/503/422/504契約で返し、0件や計算不能に偽装しない。

## スナップショットの契約

`backend/src/aggregate.rs` の `Snapshot` を両集合に使用する。取得資料やHTTP要求のJSONから集合を作らない。公開・レビュー済みデータだけを登録する。秘密情報・非公開集合はこのリポジトリのデータへ保存しない。

必要属性: unit, scope, as_of, valid_until, identity_namespace, revision, source_refs, repositories, completeness_basis, complete, expected_count, error_count, members, support_definition。

- as_of / valid_until はRFC3339。未来基準日や期限切れは不成立。
- completeだけでなく、完全性の根拠・版・出典・取得件数一致・エラー0件を必要とする。これらの申告の正しさは登録時の出典レビューで確認する。Rustの検査だけで現実世界の完全性を証明するものではない。
- 両集合の単位・範囲・時点・ID名前空間を一致させ、本番配信の定義を検査する。名前だけで事業者を統合しない。
- membersは安定した事業者ID。重複はdistinctで除外し、その件数も返す。母集団外の対応IDは黙って無視せず不整合とする。
- 出典リポジトリは検索と同じ再確認済み公開範囲で検査し、非公開になった集合の件数やURLを返さない。
- 分母0は定義不能、完全な対応集合が空なら0%。整数の分子・分母を保持し、割合のみ百分率の小数第2位に四捨五入する。
- レジストリはWorkerへ組み込むため、更新にはPRとデプロイが必要。D1への書込み・新規マイグレーションはない。

## 検証と残条件

Rust単体で重複除去・正確な丸め・0件・欠落・期限切れ・取得不全・異なる単位/範囲/時点/ID・母集団外の対応IDを検証する。実WASMでは資料件数と母数の分離、JSON/SSEの一致、ページ継続の再推論なし、曖昧時の確認、通常回答の維持、モデル障害を検証する。ブラウザーでも不足理由を表示し、ページ送りで保持する。

実モデルの指標選択精度、読取専用プレビュー、費用・遅延の許容値、本番切替と、全国母集団・本番集合の構築は別途確認が必要。これらを未確認のままIssue #51を閉じない。
